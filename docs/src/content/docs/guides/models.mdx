Pick the model SQLsaber uses for queries.

## Default model

SQLsaber uses `openai:gpt-5.6-sol` when no model is configured. `saber models reset` writes that same identifier.

The provider prefix selects the authentication route:

- `openai:gpt-5.6-sol` uses `OPENAI_API_KEY` and Platform API billing.
- `openai-codex:gpt-5.6-sol` uses [ChatGPT subscription authentication](/guides/authentication/#use-a-chatgpt-subscription).

## Recommended models

These models produce strong SQL in practice:

- `anthropic:claude-opus-5`
- `openai:gpt-5.6-sol`
- `openai-codex:gpt-5.6-sol`
- `google:gemini-2.5-pro`
- `xai:grok-4.6`

The picker also ranks a default for Groq, Mistral, and Cohere when those providers are configured. See `saber models list`.

## List available models

```bash
saber models list
```

## Set the default model

```bash
saber models set
```

This command lets you:

1. Choose a configured provider
2. Select a model
3. Save it as the default
4. Configure thinking

<Aside type="tip">
  The list is long. Type to search and filter it.
</Aside>

For scripts and coding agents, set the model and thinking level without fetching the list:

```bash
saber models set openai:gpt-5 --thinking-level medium
saber models set openai-codex:gpt-5.6-sol
```

## Override a nested model

Handoff stays on the models command:

```bash
saber models set --agent handoff
saber models set openai:gpt-5 --agent handoff
```

Plugin nested models live in plugin settings:

```bash
saber plugins setup viz --set model=openai:gpt-5-mini --yes
saber plugins setup notebook --set model=openai:gpt-5-mini --yes
saber plugins unset notebook model --yes
```

If no override is set, the nested agent uses the main model. `saber models current` lists handoff and points at `saber plugins list`.

## Reset to the default

```bash
saber models reset
saber models reset --yes
```

This writes `openai:gpt-5.6-sol` again.

## Check the current model

```bash
saber models current
saber models --help
```
